난중톡(亂中Talk) 디버깅 이력
==============================
기간: 2026-11-24 ~ 2026-11-28
범위: MVP 구현부터 배포 후 사용자 제보 대응까지(PR #1 ~ #4)
작성: 관리자 세션 (개발·디자인·리뷰(Codex) 세션 보고를 정리)

각 항목은 [증상] → [원인] → [조치] → [결과] 순서로 적었다.
남은 한계와 결정 사항은 마지막 부분에 모았다.

1부. 구현 중 발견한 문제 (MVP, PR #1)
------------------------------------------------------------

1. 정유년 8월 30일 날짜 변환 실패
  [증상] 정유년 8/30(戊子) 일기를 양력으로 바꾸지 못함
  [원인] 음력 라이브러리는 정유년 8월을 29일까지로 보는데, 일기에는 30일이 있음
  [조치] 라이브러리가 29일까지만 있는 달은 29일 + 1일로 계산하고 간지로 검증
  [결과] 1597-10-10로 간지 일치. 간지 불일치는 임진년 5·6월 15건만 남음(전서본 원문 오류)

2. Claude 번역 오역 (적재 전 시험 번역)
  [증상]
    - 射帿十五巡 → '화살을 열다섯 번'
    - 天只(어머니) → 아들 이름 '천'
  [원인] 난중일기 특유의 용어를 모델이 모름
  [조치] 번역 프롬프트에 용어 지시 추가
  [결과] '활 15순', '어머님의 부음'으로 정상 번역

3. 가장 긴 날(명량, 원문 609자) 번역이 중간에 잘림
  [원인] max_tokens 1500 부족
  [조치] 4096으로 올림
  [결과] 번역 1,475자 전체 생성

4. 장군 한 줄 소개(intro) 길이 초과로 적재 중단
  [증상] 840건 지점(을미년 8/23)에서 적재가 멈춤
  [원인] 모델이 가끔 61자 이상으로 씀. 검증 상한(60자)에 2회 연속 걸림
  [조치] 검증 상한 80자(프롬프트는 40자 유지). 캐시로 이어서 적재
  [결과] 1,593건 전부 적재, 실패 0

5. 豚薈(아들 회) → '돼지 나물' 오역
  [발견] 임진년 130건 표본 점검
  [원인] 豚은 자기 아들을 낮춰 부르는 말인데 글자 뜻대로 번역됨
  [조치] 용어 지시 추가. 임진년 전체를 다시 번역(1월만 고친 상태를 피하려고)
  [결과] 豚 35건 모두 '아들', '돼지' 0건

6. AWS 배포 차단 3건
  a) Claude 호출 거부: Anthropic 사용 사례 양식 미제출
     → 사용자가 양식 제출, 개발 세션이 재시도해 통과 확인
  b) RDS 생성 거부: 무료 플랜은 자동 백업 7일 불가
     → 백업 1일로 생성(복구는 S3 processed에서 다시 적재)
  c) RDS 생성 거부: 무료 플랜 RDS 개수 한도
     → 기존 실습 RDS 2개를 최종 스냅샷을 남기고 삭제(사용자 지시)

7. Codex 리뷰 지적 (MVP)
  - 적재 Lambda 예약 동시성 고정값 2 → 신규 계정(동시성 한도 10)에서 배포 실패
    → 파라미터화, 기본 0
  - Bedrock 408·스트림 타임아웃이 500으로 나감 → 503으로 처리, 시간 예산 25초
  - 현대 질문이 DB 장애 때 고정 답변을 못 줌 → DB 없이 고정 답변
  - 사건 키워드 오탐("그러면 죽을 뻔", "마지막으로 묻겠소") → 명시 날짜 우선, 조건 강화
  - MODERN_MARKERS 오탐: "조선 조정의 정치"도 현대 질문 처리
    → 정치·외교는 요즘·현대·오늘날·지금과 함께일 때만 현대 질문(사용자 결정)
  - 503이어도 하루 질문 횟수 차감 → 503이면 1회 환불(사용자 결정)

8. 프론트엔드 Codex 리뷰 지적
  - 예전 503 안내의 [다시 여쭙기]가 최근 질문을 다시 보냄 → 그 안내의 질문을 보내도록
  - 형식이 일부만 맞는 200 응답에서 화면 멈춤 → API 경계에서 검사·정규화
  - API Gateway 스로틀 429를 하루 한도 잠금으로 처리 → 앱 한도 문구일 때만 잠금
  - 늦게 온 오늘의 일기가 대화 순서·톤을 덮음 → 맨 위 고정 슬롯
  - KST 자정 경계에서 서버·화면 날짜 불일치 → 브라우저가 KST 월·일을 보냄

9. 명조체 글꼴 중복

  [원인] Google Fonts가 같은 가변 글꼴을 두 굵기에 내려줌
  [조치] 내용 해시로 파일 이름을 정해 하나만 저장, font-weight: 400 700으로 선언
  [결과] 248개(13MB) → 124개(6.4MB). 같은 조각을 한 번만 받음

3부. 배포 후 사용자 제보 대응 (PR #2 ~ #4)

15. "유배가셨을때 얘기해줘요"에 엉뚱한 답
  [증상] "주어진 일기들은 을미·병신·계사년 기록일 뿐…", 카드 3장은 날짜만 보임
  [원인]
    ① '유배' 계열 표현이 사건 사전에 없음
    ② 답변이 '주어진 일기' 같은 내부 표현을 그대로 말함
    ③ 출옥일(1597-04-01) 번역 오역: 得出圓門 → '원문을 나가는 것이 허락되어'
  [조치]
    - 유배·귀양·투옥·옥살이·파직·하옥·압송 → 1597-04-01 연결
      (Codex 지적으로 제3자·입옥·부정 조건 보완)
    - 1597-04-01 번역 손수정(옥문을 나오게 되어, 인명 7곳 포함)
    - 내부 표현 금지, 전제 바로잡기 지시 추가
  [오진 정정] 관리자가 처음에 카드 3장을 '빈 일기'로 진단했으나 틀렸음.
             카드가 첫 문장(날짜·간지)만 보여서 비어 보였던 것(→ 17번)

16. 전제 바로잡기 범위
  [증상] "유배가 아니라 옥에 갇혔다"고 단정
  [원인] 출옥 기록만으로는 유배 여부를 부정할 근거가 없음(Codex 지적)
  [결정] 기록이 직접 모순될 때만 정정, 기록이 없으면 유보(사용자 결정)

17. 모호한 질문 처리가 "대충 같다"는 제보
  [증상 1] 카드가 날짜·간지 문장만 보여 근거가 안 보임
    → 머리·날씨 문장을 건너뛰고 내용 문장 표시(1,593건 전수에서 빈 카드 0)
  [증상 2] 일기 밖 질문의 추천 질문이 무관하고 어색함
    → 실 API로 근거를 확인한 고정 추천 질문 8개 중 3개 표시
  [증상 3] "오늘의 장군님은 어떠셨습니까"가 일기 밖 처리
    → 오늘의 일기로 연결
  [증상 4] "12척"으로 물으면 명량 일기를 못 찾음
    → 울돌목·鳴梁, 12·13척 + 싸움 동사 → 1597-09-16
  [증상 5] "일기에 적지 않아 모르겠소"로만 시작하는 말투
    → 관련 기록을 먼저 말하게 함(평가셋 3 → 1개)
  [부작용] 새 말투 규칙이 지어낸 말을 늘림(표본 10건 중 4건)
    → "느낌·이유·결심을 덧붙이지 말 것" 보강(4 → 2건)

18. "12척으로 이긴 것이 사실?"에 "12척으로 싸운 것이 아니오"라고 부정
  [원인] 일기에 없는 숫자를 부정함(유보 규칙 위반)
  [조치] 일기에 없는 수치는 부정도 확인도 하지 않도록 프롬프트 보강
  [결과] 5회 반복 시 부정 0/5
  [한계] 5회 중 1~2회 "한 척"·"12척" 같은 일기 밖 서술
         (후처리 검사는 하지 않기로 사용자 결정)

19. 하루 질문 한도 조기 소진 (5건 안팎에 20회 한도 도달)
  [조사] 요청 1건 = 카운트 1회 확인. API Gateway 요청 수와 Lambda 호출 수 일치
  [결론] 이중 카운트 버그 아님. 과거 테스트 누적 가능성이 크지만 증명 불가(원인 불명)
  [조치] 요청별 로그 추가(client id 앞 8자, 응답 코드)

20. "과거의 오늘 어떤 일을 하고 계셨어요?"가 무관한 일기로 답함
  [원인] '오늘' 연결 표현이 좁음('오늘의 일기/장군' 등만 인정)
  [조치] '오늘' + 과거 표현·과거형 존대, '이맘때'면 연결(사용자 결정)
  [Codex 지적] '오늘 옛 친구', '올해 이맘때'까지 연결됨
    → '오늘'에 붙은 표현만, 이맘때는 수식어 없을 때만
  [결과] 세 질문 모두 오늘의 일기(1596-10-06)로 답함

21. "흥양과 순천에서 들어왔다오" — 누가 왔는지 빠짐
  [원인] 興陽，順天入來는 그 고을 수령이 왔다는 뜻인데 그대로 옮김
  [조치 1] 프롬프트에 항상 지시를 넣음
    → '배 멀미'가 8회 중 7회 막히는 부작용
  [조치 2] 묻는 날 원문에 고을 이름 + 入來 등이 있을 때만 붙임
    → Codex 지적: 探船入來·元均入來에도 붙음(214일)
    → 고을·진 이름 목록으로 한정(86일)
  [결과] "흥양과 순천의 수령이 들어왔소" 3/3, 정탐선 날은 "정탐선이 들어왔소"

4부. 남은 한계와 결정 사항
------------------------------------------------------------

[남은 한계]
- 평가 정확도(40/40)는 기준값을 정한 같은 40문항으로 다시 잰 값이라,
  실제 질문에서의 정확도는 아님. 베타 후 새 질문 세트로 재평가 필요
- '배 멀미 하셨어요?'는 같은 프롬프트에서도 20회 중 9회 막히는 경계 질문
- 명량 숫자 질문에 일기 밖 서술이 가끔 섞임
- 일기 몇 편만 보고 일반화하는 경향(예: "활은 매일 쏘셨소?")
- 그 밖의 고유명사 오역은 'AI 번역' 표기로 둠(사용자 결정)
- '오늘 아침엔 뭐 하셨어요?'처럼 목록 밖 변형은 일반 검색으로 감
- 손수정 번역(1597-04-01, 07-03, 07-10, 菶 23건)은 S3·DB에만 있고 저장소에는 없음
  → processed를 지우고 다시 적재하면 사라짐

[주요 결정]
- RDS 자동 백업 1일, Bedrock 엔드포인트 AZ 1개, 예산 알림 월 $40
- 유사도 기준값 0.22
- 전제 바로잡기는 기록이 직접 모순될 때만
- 답변 숫자 후처리 검사 없음
- 이모지 정책(normal 최대 1개)과 일기 밖 고정 문구는 유지
- 미룬 Codex Minor: 수령 문구 두 지시를 한 문장으로 정리(다음 프롬프트 수정 때)

[검증 현황 (PR #4 기준)]
- pytest 523, node 38 통과
- 평가셋 40/40
- 행동 점검: 내부 표현 0/7
